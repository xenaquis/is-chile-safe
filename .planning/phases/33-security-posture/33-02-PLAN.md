<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Job checkout step to subsequent steps in the same job | A persisted git credential (default checkout behavior) is readable by every later step in that job, widening the blast radius of any step-level compromise |
| CI static analysis to triage decision | A tool's findings are only as good as the human/agent decision of what to do with each one; an un-triaged finding is not a mitigated one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-04 | Information Disclosure | Persisted git credential surviving past the checkout step in a non-pushing job | mitigate | persist-credentials: false on all 6 non-pushing checkouts (Task 3) |
| T-33-05 | Information Disclosure | Persisted git credential in news-pipeline.yml / cead-scraper.yml | accept | These two jobs push via push-with-rebase.sh and require the credential; accepted with an inline, dated rationale rather than silently left unpinned or blanket-fixed (F-105) |
| T-33-06 | Tampering | SHA-pin regression going undetected because zizmor is assumed to cover it | mitigate | F-119 explicit note: zizmor does NOT cover SHA-pin regression at any persona; check-sha-pins.sh (Plan 33-01) is the sole gate for that axis, stated here so no summary conflates the two |
| T-33-SC | Tampering | pipx-run of zizmor (ephemeral, not installed) | accept | Version-pinned (1.10.0), invoked via pipx which ships preinstalled on ubuntu-latest (F-112); never added to pipeline/requirements.txt (SEC-04); not a slopcheck-gated install per research Pitfall 2 |
</threat_model>
