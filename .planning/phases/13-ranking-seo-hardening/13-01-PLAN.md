<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-time data → emitted HTML (`set:html` JSON-LD) | CEAD/commune/region names + URLs flow into `<script type="application/ld+json">`; a `</script>` sequence in any string value could break out of the script element. No request input (static SSG), so surface is build-data only. |
| committed binary assets → served HTML (`og:image` URL) | OG PNGs are static files; the meta references them by absolute URL. No code execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering (XSS / `</script>` breakout) | JSON-LD emitted via `set:html` in BaseLayout | mitigate | This plan PRESERVES the contract: `jsonld.ts` builders return plain objects only; the XSS-safe escape `JSON.stringify(block).replace(/<\//g,'<\\/')` lives in BaseLayout (widened in Plan 03) and is asserted by seo.mjs (every extracted block must JSON.parse without `_parseError`, which catches a broken escape). |
| T-13-02 | Information Disclosure (editorial-rule leak in machine-readable form) | ItemList `name` strings | mitigate | `jsonld.ts` FORBIDDEN guard throws on `safest`/`most dangerous`/`safe`/`dangerous` in any provided list name; seo.mjs additionally scans parsed JSON-LD string values for forbidden terms. |
| T-13-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed this phase (RESEARCH Package Legitimacy Audit: N/A). gen-og.mjs + seo.mjs use only Node builtins; no install task, so no legitimacy checkpoint needed. |
</threat_model>
