<domain>
## Phase Boundary

Pre-rendered bilingual (EN at root, ES under `/es/`) static Astro site that consumes the Phase 1 `/data/cead/` JSON contract and emits SEO-valid programmatic pages for every territorial entity: 346 communes × 2 locales, 16 regions × 2 locales, and crime-type pages × 2 locales. Pages are server-rendered HTML (no client-side rendering for SEO-critical content) with correct reciprocal hreflang, canonical tags, auto-generated sitemap, Schema.org `Dataset`/`Place` structured data, and PWA meta (manifest + theme color, no service worker). Pages read the data at build time via `getStaticPaths()`.

Requirements: PAGES-01, PAGES-02, PAGES-03, PAGES-04, SEO-01, SEO-02, SEO-03, SEO-04.

**Out of this phase:**
- Interactive Leaflet choropleth map → Phase 3 (territorial pages reserve a labeled map-placeholder slot that Phase 3 hydrates).
- Editorial/legal pages (`/is-santiago-safe/`, methodology, privacy, etc.) + forbidden-language build gate (EDIT-05) + AdSense → Phase 4.
- RSS/news incident pins → Phase 5.
- Live Cloudflare Pages deploy, custom domain, GitHub Actions cron, GSC wiring → Phase 6. **Phase 2 is build-only** (produce + verify static output).
- Detailed design tokens → deferred to the UI-SPEC produced by `/gsd:ui-phase`, which runs immediately after this context.

<decisions>
## Implementation Decisions

### Content Generation (territorial page prose)
- **D-01:** Prose is generated by a **deterministic Astro template** that interpolates real Phase-1 data into varied sentence structures. Zero API cost, fully auditable, no LLM hallucination, figures match CEAD exactly. **No LLM-generated prose** in this phase.
- **D-02:** A **high-variation engine** mitigates thin/duplicate-content deindexing risk (SEO risk #1). Variation is combinatorial, keyed off data tiers:
  - 3 trend branches (`up`/`down`/`stable`) × national-rank tiers
  - vs-national-average and vs-regional-average comparisons (sign + magnitude phrased)
  - dominant + secondary crime-family phrasing (from `by_family` of the latest complete year)
  - a **named comparable commune** with its real data (see D-05)
  - low-population statistical-volatility caveat when `low_population: true`
  - a region-context sentence
  - Goal: each commune yields combinatorially-unique prose meeting PAGES-01 (500+ words, 5+ unique data dimensions).
- **D-03:** Versions ES and EN produced with **parallel hand-maintained templates** — ES and EN strings live in the template system; data is injected into both. Zero runtime/build translation, full editorial control over sober tone in both languages.
- **D-04:** The **5 canonical unique dimensions** per commune page (PAGES-01): (1) rate vs national average, (2) rate vs regional average, (3) trend, (4) dominant crime family, (5) comparable commune. All derivable from Phase-1 JSON.
- **D-05:** Editorial sobriety is mandatory (carried from PROJECT.md): use "incidencia reportada", "tasa por 100.000 habitantes", "comparación relativa", "evolución anual". Never "zona peligrosa", "comuna peligrosa", "ranking definitivo", "zona segura garantizada". The build-time forbidden-language *gate* is EDIT-05 / Phase 4, but Phase 2 templates must already comply by design.
- **D-06:** Sparse-data / `low_population: true` communes: fill with **regional context + comparable neighbouring communes + a statistical-volatility caveat** to reach 500+ words with real, useful content — never padding, never a short page, never folding the commune into its region (keep all 346 commune pages).

### Page Composition (pre-Phase-3, no live map)
- **D-07:** Each commune/region page renders **server-side static data viz**: inline **SVG sparkline** of total rate per 100k across the full series (2005–present), national + regional rank, crime-family **breakdown bars**, vs-national / vs-regional callouts, comparable-commune block, methodology/subregistro caveat. A **labeled map-placeholder slot** is reserved in the layout for Phase 3 to hydrate with the Leaflet island — no interactive map JS ships in Phase 2.
- **D-08:** **Comparable commune (D-04 dimension 5)** = nearest commune by total rate per 100k **within the same region** (excluding `low_population` communes); fallback to nearest nationally if the region has too few qualifying communes. Always names a real commune with real data.
- **D-09:** **Component porting:** prototype components ported to **`.astro` components** for the static pages; React islands reserved exclusively for the Phase 3 map → **zero React JS on content pages** (the 346 landing pages do not load Leaflet).

### Crime-type Pages (PAGES-03)
- **D-10:** Taxonomy level: **7 crime families** — the only level present in `series[].by_family` of the Phase-1 JSON. (22 groups are NOT in current data; would require a Phase-1 re-scrape — out of scope.)
- **D-11:** Geographic scope: **national only in Phase 2** — 7 families × 2 locales = **14 crime-type pages**, each a national ranking of communes for that family. Avoids the 7×16×2 page explosion and family×region thin-content risk. (Per-region crime-type cross pages deferred — see Deferred Ideas.)
- **D-12:** The 3 **featured categories** (homicidios, secuestros, propiedad — Phase-1 D-06, lowest cifra negra) receive prioritized treatment/prominence vs the other families.
- **D-13:** Crime-type page content: national ranking of communes + family trend + sober methodology intro, with a **map-placeholder slot** so Phase 3 wires the map-filtered view in via the same slot — no re-architecture.

### Region Pages (PAGES-02)
- **D-14:** Region pages show regional aggregates + a ranking of the region's communes by rate per 100k (low-pop communes flagged/excluded from rank per Phase-1 contract).

### URL & i18n Structure
- **D-15:** `prefixDefaultLocale: false` (carried from CLAUDE.md stack) — EN at root, ES under `/es/`. Use `getRelativeLocaleUrl()` for internal links.
- **D-16:** **Localized URL segments** (user-accepted):
  - Commune: EN `/commune/{slug}/` · ES `/es/comuna/{slug}/`
  - Region: EN `/region/{slug}/` · ES `/es/region/{slug}/`
  - Crime-type: EN `/crime/{family}/` · ES `/es/delito/{family}/`
  - `{slug}` comes from `meta/index.json` (Phase 1). No collision with Phase-4 editorial slugs (`/is-santiago-safe/`, `/santiago-safety-map/`) because those live at the root under distinct slugs.
- **D-17:** Crime-family slug values **translated per locale** (EN: property, violent-robbery, homicide, …; ES: propiedad, robos-violentos, homicidios, …), via a mapping table in the i18n config. Commune slugs are shared across locales (from `meta/index.json`).
- **D-18:** **hreflang + canonical** driven by a central **slug-pair map** generated from `meta/index.json` (plus region/family catalogs), keyed by entity id (CUT / region id / family key). The base layout injects reciprocal `hreflang` alternates (`en`, `es`, `x-default`) + a self-referential canonical on every page via `Astro.currentLocale`. No per-page frontmatter hreflang (error-prone at 692+ pages).
- **D-19:** Sitemap via **`@astrojs/sitemap`** with per-locale entries (respects i18n routes automatically).
- **D-20:** Schema.org structured data (SEO-03): emit `Dataset` + `Place` JSON-LD on territorial pages, attributing CEAD as source. PWA meta (SEO-04): manifest + theme color, no service worker.

### Visual Depth
- **D-21:** **Port the prototype's visual language** (`ischilesafe.com/`): teal palette (`#0f766e`), 5-level incidence color scale (via chroma-js), header/footer, typography — as a static shell in Phase 2. The interactive map UI is deferred to Phase 3.
- **D-22:** **Defer detailed design tokens to `/gsd:ui-phase`** (runs next). Phase 2 fixes layout + base palette.

### Deploy & Batch Rollout Gate
- **D-23:** Phase 2 is **build-only** — produce and verify static output (`astro build` succeeds, page counts correct, hreflang reciprocal). Live Cloudflare deploy, custom domain, and GSC wiring → Phase 6. The roadmap SC "10–20 pages indexed in GSC before scaling to 346" becomes a **Phase 6 checkpoint**, not a Phase 2 blocker.
- **D-24:** **Batch gate (PAGES-04)** = a config allowlist (e.g. `site/src/config/rollout.json`) listing enabled commune CUT codes. `getStaticPaths` and the sitemap read this list; an env flag (e.g. `ROLLOUT_ALL=true`) overrides to build all 346. Flips the 10–20 → 346 rollout without code changes.
- **D-25:** **Initial batch** = editorial-priority communes from PROJECT.md (~12): Santiago, Providencia, Las Condes, Maipú, Valparaíso, Viña del Mar, Concepción, La Serena, Antofagasta, Temuco, Puerto Montt, Punta Arenas. (CUT codes resolved from `meta/index.json` at plan time.)
- **D-26:** Non-batch communes are **not built** (true 404) until rollout — protects crawl budget vs shipping hundreds of `noindex` pages. Regions and crime-type pages are NOT batch-gated (small fixed counts, build all).

### Claude's Discretion

- Exact SVG sparkline rendering (hand-rolled vs tiny build-time helper), exact rank-tier thresholds for the variation engine, exact Schema.org property set.
- How crime-family breakdown bars are computed (which year, featured-category ordering).
- How `/data/` is served at build (symlink vs CI copy) — follow `.planning/research/ARCHITECTURE.md`.

<specifics>
## Specific Ideas

- Pages must "look real" (prototype look ported) from Phase 2 for Google Search Console credibility and the future AdSense application — not generic scaffolds.
- Reuse the prototype's teal (`#0f766e`) palette and 5-level incidence scale (via chroma-js) so Phase 2 pages and the Phase 3 map share one visual language.
- Featured categories (homicidios, secuestros, propiedad) visually prioritized in the family breakdown — homicidios has the lowest cifra negra (most reliable statistic), per Phase-1 user intent.
- Published rates must match CEAD's published figures exactly (Phase-1 used `medida=2` official rates) so any verification against the source cuadra.
- Sparkline as inline SVG — no heavy charting library on content pages.

</specifics>
