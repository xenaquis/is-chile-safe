<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CEAD response → normalized /data/cead JSON | Untrusted endpoint data becomes the authoritative dataset served to all users |
| pipeline → repo /data (git) | Validated JSON is committed and served read-only by the static site |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Corrupted/partial CEAD scrape written as authoritative data | mitigate | validate_all_communes gate runs before any atomic_write_json; count != 346, missing keys, or rate outside 0-20000 → exit 1, zero files written, last good JSON preserved (D-14) |
| T-04-02 | Tampering | Frequency-vs-rate ranking error (raw counts in rankings) | mitigate | medida=2 only (D-10); ranks computed from rate_per_100k descending; raw counts never fetched (tipoVal police cases, never absolute count in ranking) — DATA-04 |
| T-04-03 | Denial of Service (to CEAD) | Full-run request volume | mitigate | 2.5 s inter-batch delay (D-03); region-batched (~16) not per-commune; cached raw responses allow re-parse without re-scrape (D-04) |
| T-04-04 | Tampering | Oversized map-payload degrading client | mitigate | Serialized size asserted < 30 KB before write (DATA-03 / Success Criterion 3) |
| T-04-05 | Repudiation | Published rates not matching cited CEAD source | mitigate | Use CEAD's own medida=2 rates (D-10); checkpoint spot-checks Santiago against CEAD's published value (A3) |
</threat_model>
