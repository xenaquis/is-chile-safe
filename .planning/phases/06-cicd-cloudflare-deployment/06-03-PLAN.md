<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator -> Cloudflare dashboard | Human-entered build config, secrets, domain binding |
| Public internet -> ischilesafe.com (CF CDN) | Inbound HTTPS to static assets only (no server/DB) |
| Repo secrets storage -> workflows | Secret URL + API key set by human; consumed by automation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10 | Information Disclosure | Deploy Hook URL / API key in the runbook | mitigate | DEPLOYMENT.md uses placeholders only; instructs storing real values as repo secrets, never committing them. |
| T-06-11 | Denial of Service | Rebuild loop if auto-build left enabled (INFRA-02) | mitigate | Runbook makes disabling CF auto-build the documented primary guard; includes a post-go-live build-count verification step. |
| T-06-12 | Tampering | Data commits cannot execute code on the CDN | accept | CF Pages serves only static dist/ assets; committed data is JSON consumed at build time — no runtime code execution surface. |
| T-06-13 | Spoofing | TLS for ischilesafe.com | mitigate | CF auto-provisions Let's Encrypt HTTPS; runbook requires confirming valid HTTPS at go-live (curl -I check). |
</threat_model>
