every ranking surface that currently lacks it, and applies visual polish to sort affordances
across all surfaces. No new component library is introduced — all design decisions derive from the

## Sortability — Visual Contract

These rules govern how sortability is communicated to the user across all ranking table surfaces.

### Sort Default

On page load (JS enabled), the rate column is pre-sorted **descending** (highest rate first)
for the most recent complete year. The sort arrow (▼) is visible on the rate column header
immediately without user interaction.

Implementation note: trigger `sortKey = 'rate'; sortDir = 'desc'; renderSort()` after initial
rate data-attr hydration in `RankingTableEnhancer`. This is the primary wiring task of the phase.

### Sort Affordance — Column Headers

| State | Visual |
|-------|--------|
| Unsorted | `.rte-sort-btn` — plain text, `--muted` color, cursor: pointer |
| Active ascending | `.rte-sort-btn` with ▲ glyph in `--primary`, `aria-sort="ascending"` on `<th>` |
| Active descending | `.rte-sort-btn` with ▼ glyph in `--primary`, `aria-sort="descending"` on `<th>` |
| Hover (any state) | `opacity: 0.8` (pre-existing) |
| Focus visible | 2px solid `--primary`, offset 2px (pre-existing) |

### Sort Arrow Glyph

Use pre-existing Unicode characters: ▲ (`U+25B2`) for ascending, ▼ (`U+25BC`) for descending.
Do NOT introduce SVG icons or new icon library. Aria-hidden on the `.rte-sort-arrow` span
(pre-existing).

### Year Selector

The `.rte-controls` strip (year label + `<select>`) appears above the table, flush-left, in
a flex row. Label uses `--text-label` / `--weight-strong` / `--muted`. Select uses
`--text-label` / `--ink` / `--card` background / `--line` border / border-radius 4px.
All pre-existing `.rte-controls` styles are locked — this phase does not restyle them.

### Table Rows — No-JS Fallback

With JS disabled: static server-rendered table, default sort (ascending by rate as built by
`safest-cities-in-chile.astro`). No sort UI renders. Table still has `<caption>`, `scope="col"`,
and is readable. This is acceptable — progressive enhancement.

## Specific Wiring Requirements per Surface

### `/safest-cities-in-chile/` and `/es/comunas-mas-seguras-chile/`

These two pages share the same structural gap: they render a `<table class="ranking-table">`
WITHOUT `data-ranking-table` and WITHOUT `ratesByYear` on each `<tr>`.

**Required changes:**
1. Add `data-ranking-table data-rate-col="3" data-name-col="1" data-rate-format="round" data-locale="en"` (or `"es"`) to the `<table>` element. Column mapping: col 0 = rank #, col 1 = commune name, col 2 = region, col 3 = rate.
2. Each `<tr>` in `<tbody>` must add `data-rates={JSON.stringify(ratesByYear)}` where `ratesByYear` is a `Record<number, number>` pulled from the commune data — mirrors the `CommuneRankingTable` pattern.
3. Import and render `<RankingTableEnhancer locale="en" />` (or `"es"`) after the table.
4. The Astro build-time data must expose `ratesByYear` per commune — this requires enriching the existing `communeRates` map call with `data.ratesByYear` from `loadCommune()`.
5. Default sort is descending (highest rate first) — this page currently shows LOWEST rates; on JS-enabled render the initial sort reverses to highest-first on load to match the "descending default" contract, which makes this page show highest-rate communes first. **Exception:** Because this is the "lowest reported rate" editorial page, the sort default on this surface is ASCENDING (lowest first) to preserve editorial intent. The enhancer must be initialized with `sortDir = 'asc'` on these two pages specifically. Communicate this to the planner via the per-page sort-direction override mechanism described below.

**Per-page sort-direction override:** Add a `data-default-sort-dir` attribute to the `<table>` element (`"asc"` or `"desc"`). The `RankingTableEnhancer` reads this attribute and uses it as the initial `sortDir`. Default (when absent) = `"desc"`. This is the only new data-attribute needed.

### `/communes/` directory

This page is an A-Z alphabetical commune directory (no rate column). No sort wiring applies. Polish scope: ensure the page's commune name links use `--primary` color and hover underline behavior — these are already governed by the global `a` rule. No table exists; no action needed beyond confirming correct link styles render. **No code change required unless visual audit reveals broken link styles.**

## Interaction Contracts

### Keyboard Navigation

| Action | Key | Result |
|--------|-----|--------|
| Focus sort button | Tab | Focus ring: 2px solid `--primary`, offset 2px |
| Activate sort | Enter or Space | Toggle sort direction; aria-sort updates on `<th>` |
| Focus year select | Tab | Focus ring: 2px solid `--primary`, offset 1px |
| Change year | Arrow keys in select | Table re-renders for selected year, sort order preserved |

### Mobile (< 640px)

- Table wrapper: `overflow-x: auto; -webkit-overflow-scrolling: touch` (pre-existing in `CommuneRankingTable`; must be applied to the new `.ranking-table-wrapper` on safest-cities pages too — confirm it exists).
- `.rte-controls` strip wraps via `flex-wrap: wrap` (pre-existing).
- Sort buttons inherit `<th>` touch target; ensure `<th>` has at least `padding: var(--sm) var(--md)` so effective touch target approaches 44px height. The pre-existing `CommuneRankingTable` styles already set this padding — replicate on safest-cities table.

### Low-Population Rows

Low-population rows (`data-low-pop="1"`) are sorted separately and appended after eligible rows regardless of sort direction (pre-existing enhancer behavior — locked). Visual indicator: `opacity: 0.75` + `*` superscript with `--muted` color (pre-existing). No changes.
