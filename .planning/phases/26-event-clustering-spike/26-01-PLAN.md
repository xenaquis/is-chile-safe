<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| RSS-derived headline text -> LLM prompt | `title_es`/`title_en` originate from press RSS feeds (untrusted, already ingested via the existing classifier pipeline) and are passed into the clustering LLM's user turn |
| Test/CI environment -> OPENROUTER_API_KEY | The client construction reads the env var at import time; test runs must never trigger a real network call that could leak or burn the key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-26-01 | Tampering | `pipeline/requirements.txt` (rapidfuzz install) | accept | Package already legitimacy-audited in 26-RESEARCH.md (PyPI, long-established, slopcheck `[OK]`) — no further action needed this plan |
| T-26-02 | Tampering / Spoofing | Prompt sent to `adjudicate_pair` | mitigate | Untrusted headline text confined to structurally-labeled `Titular A:`/`Titular B:` user-turn fields; system prompt explicitly frames text as DATA never instruction; unparseable/off-schema output fails safe to no-merge (CLUS-03/04) — verified by `test_prompt_injection_resistance` |
| T-26-03 | Information Disclosure | Logger calls in `_call_verdict_api`/`adjudicate_pair` | mitigate | Log only status codes, exception types, and truncated title snippets (mirroring classifier.py's `title[:60]` convention) — never log the full `messages` payload or any header/auth material; `OPENROUTER_API_KEY` is read once at import into the `client` object, never logged |
| T-26-04 | Denial of Service (cost) | Unbounded pairwise LLM calls | mitigate | `prefilter_candidates` runs before any LLM call and is a pure CPU function bounding candidate count per bucket; per-run call counting is introduced in Wave 3 (26-03-PLAN.md), out of scope for this plan but the pre-filter here is the structural bound |
</threat_model>
