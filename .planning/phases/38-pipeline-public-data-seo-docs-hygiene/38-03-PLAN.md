<objective>
HYG-03: prune the seen-ledger by first_seen, not by publication date, so old-dated feed items stop coming back as fresh candidates.

Purpose: research § 3 said "no pruning exists". That is wrong for the current tree. feeds.save_seen (feeds.py:236-253) DOES prune, keyed on the stored value, and scrape_news stores the PUBLICATION date (scrape_news.py:320, :432). So any item published more than 60 days ago is pruned on the same save and re-enters as an unseen candidate on the next run (another LLM call each run, invisible because rejected/ dedups by id within the month). Measured 2026-09-25: rejected/ holds 2 such URLs, and both are absent from seen.json. They are latercera.com/culto/2021/09/16/… (published 2021-09-16, first_seen 2026-09-17) and latercera.com/tecnologia/…review-robot-de-cocina… (published 2026-06-26, first_seen 2026-08-23).
Output: first_seen semantics with a legacy cutover, tests, scrape_news wiring.
</objective>
