<objective>
Implement the CEAD subgroup-101 (homicidios) data acquisition end-to-end
(HOM-01, D-01/D-02/D-03): a new `fetch_subgroup_batch` client function, a parallel
homicide accumulator loop in the scraper (rate + count, 2005-2025), schema
extension, normalizer wiring, and a new `homicide_rate`/`homicide_count` field in
the map-payload — emitted as a SEPARATE field, never appended to `by_family`
(which would break the 7-element family-index contract used by the chips and panel
bars). Then run the scrape so the data files are populated.

Purpose: The roadmap goal says "expose the existing per-commune homicidios data,"
but that data does not exist (featured_rates.homicidios = {} everywhere;
scrape_cead.py:448 hardcodes `{}`). This plan is the hard prerequisite that creates
the data Half B's UI consumes.
Output: Populated comuna JSON files, a regenerated map-payload with homicide_rate,
and the 14-01 test scaffold turned GREEN.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CEAD gov endpoint → pipeline | Untrusted external HTML/bytes parsed into Python and serialized into JSON the frontend trusts |
| pipeline output → committed data | The JSON written to data/cead/ is consumed downstream as trusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Tampering / Information disclosure | parse_cead_table over malformed/oversized/latin-1 HTML | mitigate | Decode latin-1 explicitly (no charset guessing); parse_cead_float clamps non-numeric markers to None; int(round()) clamps numeric output — no raw HTML string reaches the JSON values |
| T-14-04 | Tampering (data integrity) | homicide values written into committed JSON | mitigate | Pydantic MapPayloadEntry validates types (int|None); null-vs-0 invariant preserved so the frontend can distinguish "confirmed zero" from "no data"; existing validate-before-write ordering (D-14) blocks writing invalid records |
| T-14-05 | Information disclosure (secrets in data) | committed data/cead JSON | accept | No secrets in scrape output — CEAD endpoint is unauthenticated public data; no API keys involved in this path |
| T-14-06 | Denial of Service (to CEAD, courtesy) | subgroup-101 fetch loop (≈2x request volume per D-03) | mitigate | Reuse time.sleep(2.5) after every live fetch; cache-first (cache-miss only triggers a live call) so re-runs do not re-hit the government server |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | No new packages (RESEARCH §Standard Stack: requests/bs4/tenacity already installed) — no install task, legitimacy gate N/A |
</threat_model>
