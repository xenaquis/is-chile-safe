- It conflates API errors and low-confidence rejections into `parse_failure` (`:155-162`, `:217`).
- It has no usage or reasoning capture and no spend meter.

Extending it would mean rewriting all of that and changing the meaning of the Phase-16 numbers already committed. `ab_score.py` stays untouched.

**Order inside this plan (R-05 / G-10):** Task 0 (offline relabel → golden_set_v2.json + FAMILY_MIN_V2) runs first, then Tasks 1-2 (code), then Task 3 (live A/B on v2). Task 0 makes no LLM API calls. It is agent review work, not external spend.

**Ordering vs 34-02:** this plan adds only the minimal seam: a refactor of `classifier.py` into `_request_completion(...)` + `_parse_content(...)`. `classify()` behaviour is unchanged except for the R-03 balanced-object JSON recovery, which lives in the shared seam so the A/B and production parse identically. The two plans share `classifier.py`, so 34-02 is strictly after this one.
