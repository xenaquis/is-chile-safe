## Component Inventory

### New components (this phase)

All new components are Astro components or React islands following existing patterns. No third-party component library additions.

#### 1. `ComparatorIsland.tsx` — React island (`client:only="react"`)

Interactive comparator; hydrates on the `/compare/` and `/es/comparar/` pages only.

**Layout:** Horizontal flex container, 1–3 columns (commune columns) + 1 fixed "National Avg / Regional Avg" column (rightmost, always visible). On mobile (<640px), columns stack vertically; horizontal scroll is NOT used.

**Sub-components (internal to island):**

- `ComparatorSearch` — autocomplete input. Single `<input>` with `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`. Dropdown list uses `role="listbox"` with `role="option"` items. Accent-insensitive matching via `normalize('NFD').replace(/\p{Diacritic}/gu, '')`. Input placeholder: EN "Search commune name…" / ES "Buscar nombre de comuna…".
- `SelectedCommuneTag` — pill showing selected commune name + remove (×) button. Border: 1px solid --primary. Background: --card. The × button aria-label: EN "Remove {name}" / ES "Quitar {name}".
- `ComparatorColumn` — one column per selected commune. Top: commune name as `<h2>` at --text-heading. Below: composite index score at --text-display, band label at --text-label, national rank at --text-label/--muted.
- `FamilyComparisonTable` — grid table showing per-family rates side by side. Headers are family names at --text-label/700. Each row: family label + one cell per commune (rate value + trend arrow). The trend arrow uses existing TREND_ARROW symbols (↑ ↓ →) with --trend-up/down/stable colors. Homicide row: rendered as a distinct sub-row under "Life crimes", labeled EN "Homicide (per 100k, {year})" / ES "Homicidios (por 100k, {year})". Uses `featured_rates.homicidios` + graceful "No reported cases — CEAD {year}" fallback per CONTEXT.md HOM-02.
- `AverageColumn` — the "National / Regional Avg" reference column. Header: EN "Chile avg." / ES "Prom. Chile" + optional region toggle. Reads national/regional averages from `comparator_table.json`. Visual weight same as commune columns but background slightly tinted (--bg, not --card) to distinguish it as a reference, not a selection.
- `TrendChip` (reuse pattern from `TrendChip.astro`) — inline chip. In React context, render as `<span>` with role="img" aria-label="{trend label}".
- `CompositeIndexBand` — small pill: colored background from --s1..--s5 per level, label from ci_band_1..5. Matches existing `LevelChip.astro` pattern.

**Pre-rendered static shell:** The Astro page (`compare.astro` / `comparar.astro`) renders a static HTML shell with: h1, lead paragraph, and a "Loading comparator…" placeholder that the island replaces. This shell is indexable. The shell must contain the methodology caveat (reuse `MethodologyCaveat.astro`).

#### 2. `AvsBPage.astro` — static Astro page template (no island)

Server-rendered. One template for all A-vs-B pairs.

**Layout:** Single-column article layout (max-width 768px, centered). Sections in order:

1. `<h1>` — EN "{Commune A} vs {Commune B} — Reported Crime Comparison" / ES "{Commune A} vs {Commune B} — Comparación de Incidencia Delictiva". Generated via `buildComparisonProse()`.
2. **Index difference statement** (uniqueness block 1) — `<p>` at --text-body. Prose must be non-swappable (references real index scores and direction of difference). Attribution: "Source: CEAD / SPD, composite index {year}."
3. **Per-family rate table** (uniqueness block 2) — `<table>` with `<caption>`. Headers: Commune A name | Commune B name | Chile Average. Rows: 7 crime families + homicide sub-row. Use existing FAMILY_LABELS from `FamilyBreakdownBars`. Rate values at --text-label/700. Table caption at --text-label/--muted.
4. **Trend narrative** (uniqueness block 3) — `<p>` at --text-body. References actual YoY trend direction per family. Non-swappable.
5. **National rank context** (uniqueness block 4) — `<p>` at --text-body. States each commune's national rank on composite index (#X of 346).
6. **Regional context** (uniqueness block 5) — `<p>` at --text-body. Compares both communes relative to their region(s). If same region: regional rank comparison. If different regions: brief regional characterization.
7. **Cross-links to commune pages** — 2 links, one per commune, using existing `<a href="/commune/{slug}/">` pattern.
8. **MethodologyCaveat.astro** — mandatory at bottom of every A-vs-B page (per CI-06 requirement; reuse existing component).

**Forbidden language:** `buildComparisonProse()` must never emit "safe/dangerous/seguro/peligroso" in absolute form. CI-09 forbidden-language validator must exit 0. Prose uses relative language: "higher reported incidence", "lower reported rate", "ranked {X} nationally", etc.

#### 3. `ComparatorPairsLinks.astro` — snippet for commune pages

Renders 3–5 relevant A-vs-B links on each commune page.

Pattern: `<ul>` with `<li><a href="/compare/{cutA}-vs-{cutB}/">{Name A} vs {Name B}</a></li>`. Label at --text-body. Section heading at --text-heading: EN "Compare with other communes" / ES "Comparar con otras comunas".

## Comparator Island — Interaction States

| State | What the user sees |
|-------|--------------------|
| Empty (0 communes selected) | Input with placeholder, prompt text: EN "Select 2 or 3 communes to compare" / ES "Selecciona 2 o 3 comunas para comparar". No columns rendered. |
| 1 commune selected | Commune column visible, family table has only 1 data column + avg column. Prompt: EN "Add another commune to compare" / ES "Agrega otra comuna para comparar". |
| 2–3 communes selected | Full side-by-side layout. "Compare" button hidden (comparison renders immediately on selection). |
| Autocomplete open | Dropdown list max 6 visible options, scroll for more. Already-selected communes are shown in list but marked disabled (greyed, aria-disabled="true", not clickable). |
| Autocomplete no match | Single list item (not selectable): EN "No commune found — try removing accents" / ES "No se encontró la comuna — prueba sin tildes". |
| Loading commune data | Skeleton placeholder per column: grey rectangle at --line, animated pulse. No spinner. |
| Data load error | EN "Could not load data for {name}. Try refreshing." / ES "No se pudieron cargar los datos de {name}. Intenta recargar." — shown inline in the column where the error occurred, at --text-label/--muted. |
| 3 communes selected (max) | Autocomplete input becomes disabled (aria-disabled="true"), label: EN "Maximum 3 communes reached" / ES "Máximo 3 comunas alcanzado". |

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Autocomplete ARIA | `role="combobox"` on input, `role="listbox"` on dropdown, `role="option"` on items, `aria-expanded`, `aria-activedescendant` |
| Keyboard nav in autocomplete | Arrow up/down to move through options; Enter to select; Escape to close |
| Trend arrow alt text | `role="img"` + `aria-label="{trend_up/down/stable string from i18n}"` |
| Min touch target | 44px height on autocomplete options and selected-commune tag remove button |
| Color contrast | --primary #0f766e on --bg #f5f8f8 = 4.71:1 (AA). Do not lighten --primary. |
| Comparator table headers | `<th scope="col">` for commune names; `<th scope="row">` for family labels |
| Focus ring | Do not suppress `outline`; use `outline: 2px solid var(--primary)` on focus-visible |
| Static shell indexable | Astro pages render full h1 + lead + methodology caveat before island hydrates |

## Static Shell Contract (CMP-02 — SEO indexability)

The `/compare/` and `/es/comparar/` Astro pages must render the following in SSG HTML before the island mounts:

1. `<h1>` with cmp_page_h1 string
2. `<p>` with cmp_page_lead string
3. `<MethodologyCaveat />` component (existing)
4. `<noscript>` fallback: EN "Enable JavaScript to use the interactive comparator. See individual commune pages for reported crime data." / ES "Activa JavaScript para usar el comparador interactivo. Consulta las páginas de cada comuna para ver datos de incidencia."
5. Island mount point `<div id="comparator-root">` — island renders into this

## A-vs-B Page — SEO Contract

Each generated page at `/compare/{cutA}-vs-{cutB}/` must:

- Have a unique `<title>`: EN "{Name A} vs {Name B} Reported Crime Data — Is Chile Safe" / ES "{Name A} vs {Name B} Datos de Incidencia Delictiva — ¿Es seguro Chile?"
- Have a unique `<meta name="description">` at 140–155 characters using real data (index scores, top differentiating family) — generated by `buildComparisonProse()`.
- Carry `<link rel="canonical">` pointing to EN version for EN pages, ES version for ES pages.
- Carry reciprocal `<link rel="alternate" hreflang>` for EN ↔ ES pair.
- Total prose ≥ 300 words across all 5 uniqueness blocks. Build-time assertion must verify this.
