## Planning Decisions

(Carried from 27-01-PLAN.md — same decisions govern this plan's wiring; not re-litigated here, except where this plan adds its own.)

- Scope of wiring in this plan is data-layer only: add imports + the `computeNewsFacets()` call + one inert, invisible `<script type="application/json" id="news-facets">` node to each page. Card rendering markup, `monthGroups`, `safeUrl()`, and JSON-LD stay **byte-identical** — any filter UI, chips, count badges, or URL-state syncing is Phase 28 scope per the scope fence and must NOT be added here.
- `existsSync`/try-catch ownership of `current.json` parsing stays on each page exactly as today (RESEARCH Pitfall 4) — `computeNewsFacets` never does its own `current.json` I/O; it receives the already-parsed (possibly empty) `incidents` array. `newsFacets.ts` DOES own the archive-directory read, called via the page's local `public/data/incidents/archive` path.
- **Decision 11 (new, closes FM-4's hollow-deliverable risk).** Both pages emit the facet index as a single non-indexable, non-visible, machine-checkable node: `<script type="application/json" id="news-facets" set:html={JSON.stringify(facetsProjection)} />`. Use `set:html`, never plain `{expr}` interpolation inside `<script>` (Astro renders `{expr}` literally inside `<script>`/`<style>` — memory `astro-script-no-expr-interpolation` — plain interpolation would emit the literal string `{JSON.stringify(...)}`). Serialize a **counts-only** projection: `{ byFamily, byRegion, byMonth, byWindow: { today: N, sevenDay: N, thirtyDay: N } }` where `byWindow` is reduced to lengths only — **never** the full `IncidentLike[]` arrays (would add ~2.4MB per page per Planning Decision 4/FM-9). `facetKeys` is likewise excluded from this projection (build-time-only per Decision 7). This satisfies FACET-01/FACET-05 with a real, build-provable artifact instead of an unused local variable, while staying inside FACET-06 (no file written — this is inline HTML, not an artifact under `site/**`) and the Phase 28 scope fence (a `<script type="application/json">` tag is inert data, not a filter UI).
- **Decision 12 (new, F-19 — binding, non-improvisable).** `data/incidents/current.json` may fail `freshness.mjs`'s `MAX_AGE_DAYS=3` check purely because the news cron's latest commits (`origin/master`, confirmed alive via `git fetch`) have not been pulled into this local checkout — the directive reserves `git pull --rebase` for the user's return. This is an **environmental** exclusion, never a Phase 27 code defect, and is handled by the exact pre-declared branch in Task 2 below — it is not left to executor judgement.
