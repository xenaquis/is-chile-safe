## .github/scripts/require-env.sh (create exactly this content)

```bash
#!/usr/bin/env bash
# .github/scripts/require-env.sh — fail loudly if any named env var is empty.
# Usage: require-env.sh VAR1 VAR2 ...
#
# CRON-01 (F-76): the deploy-hook skip path used to be a silent no-op (a step
# reported "skipped", never failing the job). This script makes every REQUIRED
# secret (including CF_DEPLOY_HOOK_URL, per F-76 — it is no longer optional)
# a hard, first-step failure instead. Never prints a secret's VALUE, only its
# NAME, per the hard safety rule.
set -euo pipefail
missing=0
for v in "$@"; do
  if [ -z "${!v:-}" ]; then
    echo "::error::$v is not set (empty string) — refusing to proceed"
    missing=1
  fi
done
if [ "$missing" -ne 0 ]; then
  exit 1
fi
echo "All required secrets present: $*"
```

**Verified during planning** (scratchpad copy, identical content, invoked as
`bash <path>` explicitly — never as a bare executable, since Windows-committed files
can lose the x-bit):
- `OPENROUTER_API_KEY="" DEEPSEEK_API_KEY="sk-real" bash require-env.sh OPENROUTER_API_KEY DEEPSEEK_API_KEY` → exit 1, printed `::error::OPENROUTER_API_KEY is not set (empty string) — refusing to proceed`
- both blank → exit 1 (first missing var named)
- completely unset (not exported at all) → exit 1, same message shape
- both set (`A=x B=y`) → exit 0, printed `All required secrets present: A B`
- a legitimate value containing `?`, `&`, `-` (a real Cloudflare hook URL shape) → exit 0, value never echoed
- a single-space value (`X=" "`) → exit 0 (not empty by POSIX `-z`, correctly treated as present — this is intentional: `-z` checks length, not "meaningful content", and no workflow here would ever assign a space-only secret)

## .github/scripts/check-heartbeat.sh (create exactly this content)

```bash
#!/usr/bin/env bash
# .github/scripts/check-heartbeat.sh — cadence-appropriate staleness checks.
# Each mode is independently testable with a synthetic timestamp; no regex,
# plain numeric epoch-seconds comparison only (F-36 — git-bash corrupts \b in
# node -e regex, so this phase's logic stays in bash with no pattern matching).
#
# Usage:
#   check-heartbeat.sh r2   <max_age_days> <iso8601_last_run_timestamp>
#   check-heartbeat.sh cead <max_age_days> <iso8601_last_commit_timestamp>
set -euo pipefail

usage() {
  echo "Usage: $0 {r2|cead} <max_age_days> <iso8601_timestamp>" >&2
  exit 2
}

[ "$#" -eq 3 ] || usage
mode="$1"
max_age_days="$2"
ts="$3"

case "$mode" in
  r2|cead) ;;
  *) usage ;;
esac

if [ -z "$ts" ]; then
  echo "::error::$mode heartbeat: no timestamp evidence found (empty input) — treating as stalled"
  exit 1
fi

now_epoch=$(date -u +%s)
ts_epoch=$(date -u -d "$ts" +%s 2>/dev/null) || {
  echo "::error::$mode heartbeat: timestamp '$ts' could not be parsed"
  exit 1
}

age_days=$(( (now_epoch - ts_epoch) / 86400 ))

if [ "$age_days" -gt "$max_age_days" ]; then
  echo "::error::$mode heartbeat: last evidence is ${age_days}d old, exceeds ${max_age_days}d threshold"
  exit 1
fi

echo "$mode heartbeat OK: last evidence ${age_days}d old (threshold ${max_age_days}d)"
```

**Verified during planning** (scratchpad copy, identical content):
- `r2 4 "$(date -u -d '1 day ago' --iso-8601=seconds)"` → exit 0, "r2 heartbeat OK: last evidence 1d old (threshold 4d)"
- `r2 4 "$(date -u -d '5 days ago' --iso-8601=seconds)"` → exit 1, "::error::r2 heartbeat: last evidence is 5d old, exceeds 4d threshold"
- `cead 100 "$(date -u -d '10 days ago' --iso-8601=seconds)"` → exit 0
- `cead 100 "$(date -u -d '101 days ago' --iso-8601=seconds)"` → exit 1
- `cead 100 "$(date -u -d '100 days ago' --iso-8601=seconds)"` (exact boundary) → exit 0 — proves the boundary is inclusive of PASS (`-gt`, not `-ge`)
- `r2 4 ""` (empty timestamp — the "no evidence at all" case, e.g. `gh run list` returned nothing) → exit 1
- `r2 4 "not-a-date"` (unparseable) → exit 1
- unknown mode (`bogus`) → exit 2 (usage error, distinct from an age-threshold failure)
