<objective>
Run the live news pipeline in production and confirm the name→CUT resolver is assigning communes accurately, via a 50-incident hallucination audit (GL-03).

The existing `pipeline/scripts/audit_incidents.py` samples 50 incidents and prints a TSV for human eyeballing, but emits no machine-computed accuracy figure or threshold. GL-03 requires the audit to "confirm the resolver is performing at acceptable accuracy." This plan adds a scored audit mode (and a unit test for it), triggers a real `News Pipeline` run via `workflow_dispatch` using the `DEEPSEEK_API_KEY` repo secret, then runs the audit against the resulting `data/incidents/current.json`.

Purpose: Launching with a hallucinating commune resolver would mis-locate news pins on real territory — directly contradicting the editorial constraint. This proves the resolver holds in production.
Output: A scored audit over 50 live incidents reporting accuracy >= threshold, with the human-review TSV preserved for spot-check.
</objective>
