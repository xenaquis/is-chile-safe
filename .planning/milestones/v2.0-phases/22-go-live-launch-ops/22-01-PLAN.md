<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloudflare dashboard → GitHub repo secret | Deploy hook URL crosses from CF into a GitHub Actions secret; must never land in code, logs, or chat |
| GitHub Actions runner → Cloudflare Pages | `deploy-on-code.yml` curls the hook URL read from `secrets.CF_DEPLOY_HOOK_URL`; anyone holding the URL can trigger a build |
| Public push → production build | A push to master (site/**) triggers a real production deploy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Information Disclosure | CF_DEPLOY_HOOK_URL value | mitigate | URL is set only via GitHub Settings UI / `gh secret set`; never echoed, committed, or pasted into chat. Workflow reads it as `secrets.CF_DEPLOY_HOOK_URL` (auto-masked in Actions logs). Task actions explicitly forbid printing the value. |
| T-22-02 | Elevation of Privilege | Deploy hook URL leakage | mitigate | Hook URL treated as a secret (DEPLOYMENT.md §5); anyone with it can trigger builds but cannot read source or alter content. If leaked, user regenerates the hook in CF dashboard and updates the secret. |
| T-22-03 | Denial of Service | CF build quota (500/mo free) | accept | Rebuild-loop guard (auto-build OFF + paths filter + [skip ci]) caps builds; Task 3 verifies it. Residual risk low and self-limiting. |
| T-22-04 | Tampering | Accidental secret commit | mitigate | No task writes the hook value to any file; Task 4 doc update explicitly excludes secret values; grep gate on DEPLOYMENT.md is name-only. |
</threat_model>
