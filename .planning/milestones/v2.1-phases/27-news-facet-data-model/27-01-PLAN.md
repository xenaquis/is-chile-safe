## Planning Decisions

These decisions were left open by RESEARCH.md's "Claude's Discretion" / "Open Questions" sections, and further constrained/corrected by the Opus plan-checker (H1-H5, M1-M4, L1-L3) and the Opus premortem (FM-1..FM-16). They are locked here for this phase — do not re-open in execution.

1. **"Today" semantics — UTC/string-only arithmetic (amends FM-9).** Anchor "today" to the **newest incident's date** across the loaded `incidents` array. All window arithmetic is string-and-UTC only: compare `YYYY-MM-DD` strings lexicographically for equality (`today`); compute lower bounds via `Date.UTC`/`Date.parse(newestDate + 'T00:00:00Z')` — **never** `new Date(y, m, d)` (local time) and **never** `new Date(str)` on anything but a bare `YYYY-MM-DD` literal. No `toLocaleDateString`, no `getMonth()`, no local-time `Date` construction anywhere in `newsFacets.ts`. `yearMonth` is always `date.slice(0,7)`, never derived from a `Date` object. `windowToday` = `date === newestDate`; `window7d` = `date >= lower(6)`; `window30d` = `date >= lower(29)` where `lower(days) = new Date(anchorMs - days*86400000).toISOString().slice(0,10)` and `anchorMs = Date.parse(newestDate + 'T00:00:00Z')`. A `facets.mjs` determinism assertion runs the window computation under both `TZ=UTC` and `TZ=America/Santiago` and asserts identical bucket sizes.

2. **Facet scope:** `byFamily`/`byRegion`/`byWindow` counts are scoped to **`current.json` only**. `byMonth` is a **separate dimension** built as the **union of archive months and months observed in `incidents`** (amends FM-6) — never a merged pool with `byWindow`. Rationale: `current.json` spans `2026-06-29..2026-07-27`; the archive holds only `2026-04` and `2026-06`; a `byMonth` sourced from the archive alone would silently omit July (1,204/1,215 incidents) and double-represent June. Each `MonthBucket` carries `source: 'archive' | 'current' | 'both'` and, when `'both'`, an additional `currentCount` field so Phase 28 can tell the two counts apart instead of assuming they mean the same set. Archive file shape is `{generated, window_days, incidents: [...]}` (an object, not a bare array): `count = (parsed.incidents ?? []).length`; a file that parses but lacks an `incidents` array counts 0 and is still listed, never thrown away.

3. **Sort order per facet:** `byFamily` — descending by count. `byRegion` — ascending by **numeric** `Number(regionId)` (never string sort, which yields `1,10,11,...,2,3`), while `regionId` itself stays a `string` throughout the output shape. `byMonth` — descending by `yearMonth` string (newest first).

4. **Module shape:** One default export `computeNewsFacets(incidents: IncidentLike[], index: CommuneMeta[], archiveDir?: string): NewsFacetIndex` returning `{ byFamily, byRegion, byWindow, byMonth, facetKeys }`. Plain exported `interface`s, no class. `computeNewsFacets` receives already-parsed `incidents` as a parameter — it never does its own `current.json` I/O (Pitfall 4); it DOES own archive-directory reading with per-file `existsSync`/try-catch. **`byWindow`'s three arrays are for build-time consumption only — never serialize them into rendered HTML** (three arrays over 1,215 incidents would add ~2.4MB per page); only their `.length`s may ever be surfaced downstream.

5. **Family key set:** Derived from `new Set(incidents.map(i => i.family).filter(Boolean))` — never from `Object.keys(FAMILY_LABELS_EN)`. `FAMILY_LABELS_EN`/`FAMILY_LABELS_ES` are imported for display-label lookup only, on keys actually observed in data.

7. **Counts are unconditioned marginals (new, amends FM-7).** `byFamily`/`byRegion`/`byMonth`/`byWindow` are four independent marginal tallies over the full `incidents` array — there is no active-filter parameter. To let Phase 28 build a real cross-tabulated facet UI without recomputing from raw incidents client-side (which would reintroduce the exact per-locale drift FACET-01 exists to eliminate), `computeNewsFacets` additionally returns `facetKeys: Array<{ id: string; family: string | null; regionId: string | null; yearMonth: string; window: 'today' | '7d' | '30d' | 'older' }>` — one small per-incident record, derived by the same code that builds the marginals so they cannot drift (~40 bytes/incident, never serialized wholesale into HTML per Decision 4 — Phase 28 consumes it at build time only). **Phase 28 MUST cross-tabulate from `facetKeys`, never recompute facets from raw incidents.** `regionId` is a `string` throughout (`data/cead/meta/index.json` stores it as a string, values `'1'..'16'`) — never coerced to a number in the output shape; only the *sort comparator* uses `Number(regionId)`.
