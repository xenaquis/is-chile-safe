## Operating lessons from Phase 26 (added 2026-07-29 — apply to every remaining phase)

These were learned the hard way in Phase 26. Do not rediscover them.

1. **`gsd-executor` has NO Agent tool** (its registry grants Read/Write/Edit/Bash/Grep/Glob only). Any plan step that requires spawning an independent reviewer, a blind second opinion, or a parallel sub-analysis **must be executed inline by the orchestrator**, not delegated to an executor. Leaving such a step inside a plan produces either a silently-skipped gate or a self-review by the same agent that produced the work. Split the plan dispatch into orchestrator-managed steps instead (Phase 26 Wave 2 was dispatched in three: executor draft -> orchestrator blind pass -> executor finalize). Same applies to Phase 29: BrowserOS work runs inline.
2. **Audit BOTH error directions before issuing a verdict.** A gate that guards one direction (e.g. confirming `merge` labels) leaves the opposite direction (a wrong `no_merge` fabricating a false positive) unguarded. Before signing any GO/NO-GO, verify the labels/assumptions that *drive* the verdict, not just the ones the protocol happens to name.
3. **A verdict that cannot fail is not a verdict.** Any measurement must have a defined, green-closing path for BOTH outcomes before execution starts. Phase 26's NO-GO branch originally could not close with a green suite; `xfail(strict=True)` is the pattern that resolves this — the failure stays encoded and re-arms if a future change passes, instead of being hidden by a weakened assertion.

## Operating lessons added at Phase 27 close (2026-07-30)

8. **Audit every `<automated>` verify block for exit-code laundering — this is the defect that survives being described correctly.** A gate's exit status must never pass through a pipe, a `;`, or a trailing `|| echo`. `cmd | tail` reports `tail`'s status, which is always 0, so `npm test 2>&1 | tail -30` reports GREEN on a suite with 8 failures. In Phase 27 this defect was found **four separate times**, including once where the plan contained correct prose banning `; echo "EXIT:$?"` and committed the same class of defect one line below it. Grep every plan for `| tail`, `| head`, `; echo`, `|| echo` inside verify blocks before approving it.
9. **A check that "cannot pass" is as bad as one that "cannot fail", and both hide in new code.** Phase 27 shipped, at various points: a guard that threw on a *correct* build (`empty-state` is a CSS class Astro inlines into every page); a validator assertion that scanned its own source for the patterns it necessarily contained (so it always exited 1); a validator assertion whose conclusion was contained in its own construction (a tautology); and a dead branch that was unreachable by definition. For every new assertion, construct a counterexample and prove it exits non-zero — falsifiability is not optional, and an assertion that cannot fire is worse than none because it reads as coverage.
10. **Verify the REVIEWER's proposed fix too, not just the executor's work.** The Opus re-review's RR-1 remedy ("assert the rendered node contains no raw `<`") could not detect the regression it was written for: with real data, escaped and unescaped output are byte-identical, so the control could be deleted invisibly. Only a source-level assertion caught it. A finding being correct does not make its suggested fix correct.
11. **Mutation-test every test added during a fix cycle.** Phase 27's spec passed 16/16 while the 7-day window's boundary width was completely unpinned; the 30-day equivalent was pinned. Break the exact behavior a new test claims to cover, confirm RED, restore, prove the tree is clean.
12. **When an Opus subagent is unavailable (`529 Overloaded`), escalate — never downgrade the reviewer to Sonnet.** Sonnet reviewing Sonnet's own output is the circularity F-06/F-11 exist to prevent. Do the review inline as Fable, then get an independent Opus re-review once the API recovers, so the two-model separation is restored before the phase closes (F-23).
13. **The GSD SDK sometimes rewrites `STATE.md`'s `progress:` frontmatter to cross-milestone totals** (it set `total_phases: 14 / completed_phases: 6` mid-phase). v2.1 semantics are 8 phases. Check that block at every phase close.

## Operating lessons added at Phase 28 close (2026-07-30)

14. **A green gate suite is evidence about the gates, not about the code.** Phase 28's implementation passed 21 validator assertions, 36 vitest tests and a clean astro check — and two Opus review cycles then found **ten real defects**, including that NEWSUI-02, the phase's single headline invariant, had **no gate at all** (the card-count regex matched a `hidden` card identically to a visible one). 15. **The fix cycle needs the same adversarial reading as the original work — it will trade one defect class for another.** Phase 28's cycle 1 closed a false negative in the comment-stripper by introducing a false positive (a trailing `// never use innerHTML here` comment failed the build), and its own fix for WR-01 shipped completely ungated — reverting the fixed line left 21/21 assertions and the whole vitest suite green. ## Operating lessons added at Phase 30 close (2026-07-30)

19. **The fix cycles are where the damage happens, and re-running the whole instrument is the only thing that catches it.** Phase 30's cycle 1 closed all 13 review findings and introduced **three** regressions — including pushing coverage at 375 px from 21.7 % to 27.4 %, past the one threshold `STRESS.md` freezes — because two independently-correct fixes interacted (keeping the state summary visible grew the topbar). 20. **A test you wrote can be one whose failure is impossible — including yours.** My close-pass "proof" that `?cut=` beats `?region=` used `?cut=13101&region=05`, and `region=05` resolved to nothing at the time, so the test could not have failed. The reviewer found it. Before trusting any test you authored, ask what would have to be true for it to go red, then make that true once.
21. **Measure in a visible tab, and never trust a synthetic event for native browser behaviour.** Leaflet runs neither `fitBounds` nor tile fetches in a background tab — measured hidden, a working deep link, a broken one and a plain load are byte-identical, which reads exactly like a silent no-op and cost a full diagnosis. Likewise a `<dialog>` ignores a synthetic `KeyboardEvent('Escape')`: the `close` event does not fire, which looks like a wiring defect and is not. Phase 29's `closeEventsFired: 0` finding may well have been this same artifact.
22. **When an instrument and a correct implementation disagree, say so and evidence the ground truth — do not edit either to agree.** Roving tabindex is the WAI-ARIA-mandated radiogroup pattern and it sets `negativeTabindexCount: 9`, which `score.mjs` reads as a keyboard trap. The options were to weaken the instrument (banned by F-49), to revert a real accessibility fix to protect a metric, or to record the false positive with a real Tab walk attached. The third is the only honest one — and the same shape as F-51 (c3's document-wide scan) and F-57 (c2's Leaflet tile pane). Expect roughly one of these per phase that uses a shared instrument, and decide it explicitly rather than at close under pressure.
23. **Rebuild the "before" when a before/after number stops being comparable.** Phase 30's raw coverage metric appeared to regress 21.9 % → 29.4 % at desktop. Checking out the pre-phase source, building it, and measuring both through the identical harness showed union coverage of 21.2 % on **both** — the raw jump was entirely the `data-role` hooks the spec mandates, counted 2–3× because they nest. Ten minutes of rebuild replaced an argument with a measurement, and it changed the verdict.

24. **A grep returning zero is evidence about the grep — and the rule binds the orchestrator too.** Phase 31's inverted `national_rank` claim was found **five times, in five different phrasings, across four separate sweeps**; each sweep declared the site clean and each was wrong, because every pattern was written against the phrasing of the instance last found.
