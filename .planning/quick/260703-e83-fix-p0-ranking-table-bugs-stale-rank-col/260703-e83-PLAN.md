<objective>
Fix three P0 ranking-table bugs confirmed today against production (ischilesafe.com):

1. Stale Rank column + stale heading year when the user changes the year select on ranking tables (misleading data — rank shown is always the latest-year rank regardless of selected year).
2. Mass internal 404s: commune pages emit up to 5 comparator links per page using canonical pair slugs without checking `enabled`, but only 20 compare pages are built (all region 10). Providencia links `/compare/13101-vs-13123/` which is a live 404.
3. Similar-communes table on all 692 commune pages ships the sortable enhancer but renders static because `nearestComparables()` returns rows without `ratesByYear`, so the enhancer hits its `hasRatesData` guard and bails.

Purpose: Remove misleading rank data on year change, eliminate thousands of internal 404 links (SEO damage), and make the advertised sortable similar-communes table actually function.
Output: Progressive-enhancement fixes (vanilla JS, zero new deps, zero client:* directives), symmetric across EN + ES mirrors, all pages remaining fully pre-rendered static HTML. spine.mjs assertion M updated so the comparator fix does not break the build gate.
</objective>

Teach RankingTableEnhancer about two new optional, backward-compatible table-level attributes, keeping everything vanilla JS with zero new deps.

(a) data-rank-col: a comma-separated list of 0-based td indices holding rank/position values that are only valid for the default (latest) year. Parse into an array of ints (empty/absent = no rank columns). On the enhancer's initial pass (the same init loop that seeds numericRate, around lines 251-260), for each row store the original text of each rank cell in a data attribute on that cell (e.g. dataset.origRank = cell.textContent). Inside renderSort(), AFTER rewriting rate cells, iterate rank cells: if `selectedYear === years[0]` (the default/latest year) restore `cell.textContent = cell.dataset.origRank`; otherwise set `cell.textContent = '—'`. This makes rank blank for non-default years and restores it when the user returns to the latest year. Do not touch rank cells at all when data-rank-col is absent (preserves current behavior for tables without a rank column).

(b) data-year-target: any element carrying this attribute should have its textContent set to String(selectedYear) whenever the year changes (and on init). Query `[data-year-target]` document-wide once per enhanced table is wrong (would double-apply for multiple tables) — instead query within a scope tied to the table's page section, OR query globally but guard idempotently by always writing the current selectedYear. Simplest correct approach: in renderSort(), after the rank-cell pass, run `document.querySelectorAll('[data-year-target]').forEach(el => el.textContent = String(selectedYear));`. Because the crime-ranking page has exactly one enhanced ranking table driving the heading, global write is safe. (If a page had two independent tables this would be ambiguous — none of our pages do; note this assumption in a code comment.)

(c) Optional data-rank-note: if the table has a `data-rank-note` attribute (localized literal text supplied by the page), create a small muted note element appended to the controls strip; show it only when `selectedYear !== years[0]`, hide it otherwise.
