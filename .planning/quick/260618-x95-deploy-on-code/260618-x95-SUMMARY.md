# Phase quick-260618-x95 Plan 01: Deploy on Code Push Summary

**One-liner:** Push-triggered Cloudflare Pages Deploy Hook via GitHub Actions for `site/**` code changes, with dry-run-safe secret gating.

## What Was Built

Created `.github/workflows/deploy-on-code.yml` — a GitHub Actions workflow that POSTs the
Cloudflare Pages Deploy Hook whenever a push to `master` touches `site/**` or the workflow
file itself.

**Design decisions:**
- `paths: site/**` and `.github/workflows/deploy-on-code.yml` only — `data/**` is deliberately
  excluded. Data commits carry `[skip ci]` and touch only `data/`, so they already won't match;
  the exclusion is defense-in-depth and documents intent.
- `CF_HOOK` is a job-level env var (CR-01 from news-pipeline.yml) so it is in scope for
  `if:` conditions. A step-level env var is NOT available to that same step's `if:`.
- Missing/empty secret: `if [ -z "$CF_HOOK" ]; then echo ...; exit 0; fi` guard makes the run
  succeed silently — dry-run safe for repos without the secret configured.
- `permissions: contents: read` (least privilege — no checkout, no write).
- No `actions/checkout` needed — the job only curls a URL.
