# v2.2 Site Audit — 2026-09-22

Multi-lens audit (corrida-autonoma: 7 lenses opus/sonnet/haiku + fresh opus arbiter, xhigh). Repo HEAD 7c32fd7. Read-only.

## Executive summary

Arbiter verdict. I verified everything read-only against the repo at HEAD 7c32fd7, the live site, gh and the public OpenRouter catalog.

**Headline.** Since 2026-09-04T20:12Z the news layer has been dead and nothing has alerted. Three defects combine:
- **V-01:** the default classifier model `ibm-granite/granite-4.1-8b` is hard-coded, and OpenRouter no longer serves it (`/endpoints` returns 0 endpoints).
- **V-02:** every API error is swallowed as a permanent "classifier_none" rejection and the URL is marked seen before classification. 2,073 items are lost this way, 2,072 of them in seen.json.
- **V-03:** the job exits 0, and both the heartbeat and freshness.mjs check `current.json.generated`, which every run rewrites. Result: 20/20 heartbeats green, 6/6 recent runs green, zero news alert issues ever opened.

**Recovery is cheap.** rejected/2026-09.json holds exactly the classifier's inputs, so the lost items can be reclassified without refetching.

**Deadline.** current.json holds only 2026-08-23..2026-09-04. On 2026-10-05 it empties, and with it /news/, the map pins, the commune news sections and the home news block.

**New problems I found myself (measured):**
- **Duplicates on prod.** One arrest story appears as 7 separate cards. Its English headlines variously call the arrested man "Grandfather", "In-law", "father-in-law" and "nephew-in-law" of a named real person; the source URL says yerno (son-in-law).
- **Cross-run duplicates.** Dedup never runs against existing incidents. The pipeline's own 0.82 rule would drop 73 of 807 current incidents.
- **Misfiled incidents.** In a 30-item spot check, about 12/30 "vida" items are not crimes against life. They include a prison suicide rendered on /es/noticias/ as "Delitos contra la Vida", a traffic death, and a maltrato-habitual (domestic violence) case.
- **False zeros.** The news histogram shows zero incidents for Aug 6-22, days that actually had incidents.
- **Public ledgers.** seen.json (2.0MB) and the rejected corpus (2.0MB of third-party snippets) are served publicly at /data/incidents/.

**How I resolved contradictions between lenses:**
1. Outage start and size ("since 09-01, ~1,900" vs "since 09-04, 2,073" vs "2,296"): decided by per-day rejection_stage counts keyed on first_seen, plus the run logs. Sept 1-4 show mixed genuine stages; from 09-05 on it is 100% classifier_none. The onset matches first_seen 2026-09-04T20:13:49Z. 2,073 is correct; 2,296 wrongly includes 223 genuine pre-outage rejections.
2. Newest incident date (08-23 vs 09-04): measured max(date) is 2026-09-04. 08-23 is the minimum.
3. Freshness validator ("failing every build" vs "false green"): the code reads `generated` = 2026-09-22T20:49Z, so it passes (false green).
4. Retry ("no retry" vs "retries once"): classifier.py:162-166 does one immediate retry on any None, including 404/401, with no backoff.
5. BioBio mojibake (the build lens rated it a CONFIRMED P1): the data files contain 0 U+FFFD byte sequences, and the example is stored as valid UTF-8 "exlíder". REFUTED; only the octet-stream log noise remains.
6. "CEAD stale, no recovery" (P1): commit 39af2a3 and the issue #2 comment show a local scrape on 2026-08-06 returned byte-identical data, so CEAD had published nothing new. REFUTED. What remains is the Oct-1 local scrape.
7. "No CEAD freshness monitor": the heartbeat has a quarter-boundary check that will fire when 2 quarterly due dates have passed, i.e. from 2026-10-01. REFUTED.
8. "Data-only pushes never deploy": deploy-manual.yml has existed since 2026-08-06. REFUTED; STATE.md is stale on this.
9. Astro critical RCE (P1): the advisory is real and PR #39 is CLEAN/MERGEABLE. But the site is static, has no astro:assets / `<Image>` usage and no AVIF files, so the vulnerable code path is never reached. Downgraded to P2.
10. Dependabot counts: 16 open alerts (not 27; 29 total) and 17 open PRs.

**Proposed milestone: v2.2, Phases 34-38.**
- 34: restore classification, add fail-loud guards and backfill, before 2026-10-05.
- 35: make the site's freshness signals honest.
- 36: fidelity and attribution (verbatim headlines, family accuracy, Google News decoding, cross-run dedup).
- 37: dependency and security hygiene.
- 38: pipeline, public-data and SEO hygiene, plus docs drift.

The locked decisions stand: no LLM event clustering or merging, CEAD FAMILY_KEYS stay at 7, the CEAD scraper stays local-only, and national_rank keeps its direction.

### V-01 — Default classifier model ibm-granite/granite-4.1-8b is hard-coded and delisted on OpenRouter (single endpoint, no fallback, no preflight)

**Severity:** P0 · **Verdict:** CONFIRMED · **Sources:** NC-01, LIVE-F1, CICD-F1, CRIT-001

**Evidence:** Code: pipeline/news/classifier.py:58 sets NEWS_PROVIDER default 'openrouter', and :73-79 sets _MODEL = "ibm-granite/granite-4.1-8b" with no env override. news-pipeline.yml:44-47 notes that nothing sets NEWS_PROVIDER.

OpenRouter, checked by the arbiter:
- GET openrouter.ai/api/v1/models lists 454 models and granite-4.1-8b is not among them.
- GET /api/v1/models/ibm-granite/granite-4.1-8b/endpoints returns 0 endpoints.
- granite-4.2-8b (created 2026-08-31) has 2 endpoints: DeepInfra $0.06/$0.25 and CoreWeave $0.10/$0.15 per 1M.
- deepseek/deepseek-v4-flash has 15 endpoints, $0.04-0.21 input and $0.098-0.56 output.
- deepseek/deepseek-v4.1-flash is new (2026-09-10) and has not been validated.

Latest run 35782684590: 'fetched=387, keyword_passed=133, unseen_candidates=21', with 87 log lines containing 404 ('POST .../chat/completions "HTTP/1.1 404 Not Found"'). gh secret list shows both OPENROUTER_API_KEY and DEEPSEEK_API_KEY (the latter set 2026-06-19; whether that account still has funds is unverified). clustering.py:60 carries the same dead constant but is not on the production path (V-26).

REFUTED sub-claim (CRIT-001) that the outage began 2026-09-01: see V-24.

**Proposed fix:** 1. Make the model configurable (NEWS_MODEL env or config constant) with an owner-chosen default.
2. Add a startup preflight that calls GET /api/v1/models/{id}/endpoints and fails the run loudly when it returns 0 endpoints.
3. Optionally add OpenRouter's `models` fallback list. Its fallback behaviour is untested live.
4. Before switching, validate the replacement with the eval runner (V-08).
5. Update DEPLOYMENT.md and data/SOURCES.md, which name Granite 4.1.

### V-02 — API failures are recorded as permanent 'classifier_none' rejections and burned into seen.json, so the outage items are never retried

**Severity:** P0 · **Verdict:** CONFIRMED · **Sources:** NC-02, LIVE-F2, BUILD-F1, CICD-F3, CRIT-002

**Evidence:** Code:
- scrape_news.py:303 sets `seen[item["url"]] = item["date"]` before classify() (CR-02).
- scrape_news.py:306-312 records any None as rejection_stage 'classifier_none'.
- classifier.py:231-247 converts AuthenticationError, RateLimitError, APIStatusError (404) and any other Exception into None.

Measured by the arbiter in rejected/2026-09.json:
- 2,308 items: classifier_none 2,296, commune_null 7, resolver_fail 5.
- 2,073 items are classifier_none with first_seen >= 2026-09-04T20:13:49Z, and 2,072 of those are in seen.json (7,077 entries).
- Per first_seen day, Sept 1-4 have mixed stages (genuine rejections). From 09-05 to 09-22 there are 81-144 per day, all classifier_none.

Only one tool reads stored rejects (repair_sexual_family.py), and it does not cover this case.

**Proposed fix:** 1. classify() returns a typed outcome: OK, NOT_CRIME/LOW_CONF, PARSE_ERROR, or API_ERROR(status).
2. An API_ERROR does not mark the URL seen and is not written to rejected/ as classifier_none. Instead the full payload (title, description, date, outlet, url) is persisted to a retry queue, e.g. data/incidents/pending.json, with an attempt counter and a max age. The queue is needed because RSS items rotate out of the feed, so leaving them unseen alone would lose them.
3. Add a circuit breaker: after N consecutive API errors, stop calling the API for the rest of the run.
4. Keep CR-02 semantics for genuine model rejections.
5. Update the CR-02 tests.

4. `generated` changes only when the incident set changes (see V-12).

### V-04 — The 2,073 outage items can be backfilled exactly from rejected/2026-09.json, and it must happen before 2026-10-05

**Severity:** P1 · **Verdict:** CONFIRMED · **Sources:** NC-05, NC-06, BUILD-F1, LIVE-F2, CICD-F3, CRIT-002

**Evidence:** Stored inputs:
- record_rejected (scrape_news.py:66-121) stores url, outlet, date, title, description = strip_html(desc)[:500] and first_seen. classify() reads title + description[:500] (classifier.py:159).
- Sample keys verified: id, url, outlet, date, title, description, rejection_stage, first_seen.

The outage set (measured):
- 2,073 items; publication dates run 2021-09-16..2026-09-22, and only 1 is dated before 2026-08-23.
- 1,089 of them are Google News URLs. That does not matter here because the classifier does not fetch the article.

Window and deadline:
- store.py:138-163 sets cutoff = today - 30 days.
- current.json covers 2026-08-23..2026-09-04 (807 incidents; 36 on Sep 4), so it empties on 2026-10-05.

Race risk: news-pipeline.yml uses concurrency group 'news-pipeline' and commits data/incidents every 6h.

The R2 corpus (archive_r2.py consolidate_rejected) currently counts these API failures as classifier rejections (NC-06).

Expected yield: before the outage there were about 50-70 genuine classifier_none per day against 36-106 accepted per day, so roughly half of the 2,073 should be accepted. This is an estimate, not a measurement.

Cost: 2,073 × ~3.3k input tokens (lens estimate of prompt size) ≈ 6.8M tokens. That is about $0.33 at $0.049/M (deepseek-v4-flash, StreamLake) up to about $1.4 at Azure pricing.

**Proposed fix:** 1. Write pipeline/backfill_classifier_outage.py with --since, --dry-run, --limit and --r2 options, following the repair_sexual_family.py pattern. It selects stage=='classifier_none' AND first_seen >= 2026-09-04T20:13:49Z, runs classify, resolve_cut, centroid, build_incident, dedup against the existing current.json (V-11) and merge_and_write, then rewrites each row's real stage or removes it if accepted. seen.json stays untouched.
2. Run it as a workflow_dispatch job in the 'news-pipeline' concurrency group, or with the cron paused, so it does not race the scheduled commits.
3. It requires the V-02 retry semantics first.
4. Re-run archive_r2 so the R2 rejected.jsonl and corpus-state are corrected.

### V-09 — Retry semantics are wrong: one immediate retry on any failure (including 404/401), no backoff for 429/5xx, tenacity not used

**Severity:** P2 · **Verdict:** CONFIRMED · **Sources:** NC-11, BUILD-F3

**Evidence:** classifier.py:162-166: whenever _call_api returns None, the code logs 'Empty %s response … retrying once' and calls again at once. The contradiction between the two lenses ('no retry' vs 'retries once') is settled by the code: there is exactly one immediate, unconditional retry.

Latest run: 21 'retrying once' lines for 21 candidates.

requirements.txt pins tenacity==9.1.4, and it is used in cead/client.py and fulltext.py but not in classifier.py.

**Proposed fix:** 1. Retry only on empty content and on 429/5xx/connection errors, with exponential backoff (tenacity).
2. Fail fast on 401/403/404 and log the status class.
3. Combine with the V-02 typed outcome and circuit breaker.
